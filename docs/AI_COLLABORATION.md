# AI 协作与人工审查记录

每次开发填写以下模板，保留真实失败与修复。示例不作为已经发生的审查成绩。

| 字段 | 记录 |
| --- | --- |
| 目标 / 人做的取舍 | 为什么开发这一块，明确不扩展的范围 |
| 给 Coding Agent 的约束 | 接口、权限、不可违反的行为、验收编号 |
| 生成物 | 文件 / commit / 依赖版本与许可证 |
| 审查 | 输入路由、E、隐私、幂等、错误处理、时间规则 |
| 拦下的问题 | 真实错误、证据、修改与原因；没有就写无 |
| 验证 | 命令、结果、AC 对应证据；模拟和真机分开 |
| 未解决问题 | 条件、影响、下一步 |

可用的窄任务提示：

> 实现 SessionBroker，动作必须绑定 sessionId/E/observationId/actionId。接管先增加 E，再等待已准入动作结束。不得把取消协程当作系统输入已取消。为迟到模型响应和接管期间的在途动作写行为测试。不要添加 Android 权限或默认屏回退。

审查重点：

- 每个实际输入动作是否经过同一个 Broker；检查与派发间有没有竞态。
- 所用窗口是否仍属目标 display/package；不存在 rootInActiveWindow 回退。
- 邮件内容能否改变工具权限；是否将截图、密钥或完整链接写日志。
- 是否在保存前记录 PENDING，未知结果是否查目标而非重试保存。
- 是否使用 IANA 时区，是否在新鲜 GUI 中重开并核实结果。
- 是否绕开 GUI、偷偷写入 Calendar Provider 或发送邀请。
- 是否把编译成功、模拟数据或预览截图冒充真机成功。

典型错误仅作审查示例：SET_TEXT 后直接声称搜索成功；悉尼写死 UTC+10；暂停立即授权人工而忽略在途动作；保存超时再点一次。

## 第一轮：框架

从空仓库搭建工程。技术边界来自已确认方案；所有真机隔离、兼容性与速度结论保持待验证。实际构建、测试和修复结果在完成后追加。

真实修复记录：

- AIDL 首次编译拒绝混合自动编号与 Shizuku destroy 的显式编号。全部方法改为固定 transaction ID，保留 destroy=16777114；以重新构建确认。
- 审查发现等价时间字符串（有/无毫秒）会生成不同去重键。先标准化为 Instant，再生成摘要，增加行为测试。
- 审查发现停止中的会话若仍有在途输入，不能立刻复用同一 displayId。增加准入条件与并发测试。
- lint 提示新版 Android 需要显式 dataExtractionRules。补充云备份与设备迁移排除规则，避免只依赖 allowBackup 的隐含行为。

以上记录是构建/代码审查结果，不代表已经通过真实手机输入隔离验收。

第一轮本地检查：31 项 core 测试通过；调试 APK 与签名验证通过；lint 0 错误、9 条保留提示。新增备份与图标资源后重新跑 Android 构建和 lint，结果通过。详见 evaluation/LOCAL_CHECKS.md。

## 第二轮：邮件到日历工作流

用户要求先推送框架，再继续按 TASKS 实现代码闭环，跳过真机。保持单执行 Agent、GUI 读邮件、双会话、唯一日历写入者、手机直连模型。没有为绕过设备缺失而接入日历直接写 API，也没有调用用户的真实邮箱或模型密钥。

给 Coding Agent 的约束：

> 用普通代码实现 MailCalendarWorkflow，模型仅做一次计划、招聘事项提取和当前界面的单步决策。所有动作绑定 sessionId/E；模型不得点击最终保存。保存前必须持久化 WRITE_PENDING。真实 App 重开证据不足时返回 UNKNOWN，重跑先查，不重放保存。用三封固定邮件通过模拟端口测试生产编排，并将这些结果和设备验收分开报告。

审查与修复的真实记录：

| 问题 | 证据 / 处理 |
| --- | --- |
| GitHub 首次 CI 请求已移除的 Android `tools` 包 | 远端失败日志定位；setup-android 只安装 platform-tools，后续框架 CI 通过 |
| 日历备注中的原文时间被当作实际时间字段 | 本地控件树测试出现多余忙碌区间；核实/冲突解析排除备注及子控件，回归通过 |
| 模型耗时导致最初观察过期 | 派发前重新观察；界面变化丢弃旧决策，慢响应与接管迟到响应测试通过 |
| 只看 marker 不能证明内容完整，模糊时间匹配可能误报 | 本地审查补充完整备注、账户词边界、日期数字边界及 AM/PM 比较测试 |
| 模型高置信度也可能给错 UTC 或 sourceZone | 增加独立 TimeGrounding；两类高置信度错误均进入确认 |
| 去重放在冲突之后会和自己的记录冲突 | 来源规范快照和标记查询前置；重跑不重复提取、不重复保存、不重复问自身冲突 |
| 普通导航可能通过任务完成复选框或编辑框 IME 提交产生副作用 | 模型权限屏蔽 checkable；SubmitSearch 只准真实搜索字段；保存由普通代码消费一次票据 |
| 冲突确认后日历可能变化 | 再次读取并比较事项/区间/覆盖摘要，变化触发二次确认测试 |

本轮验证：67 项 core 行为测试通过，APK 构建和签名验证通过，lint 0 错误 / 13 条提示。模型、GUI 端口、设置/确认页及状态胶囊已编译接入；在线请求、真实 GUI、焦点/音频/流畅度均未测试。原地触摸和放大小窗仍未实现。完整机器结果见 [本地检查](../evaluation/LOCAL_CHECKS.md)。

## 第三轮：胶囊、小窗与人工触摸

用户要求实现胶囊点击入口、原地接管、双击放大，真机继续跳过；完成本地检查后推送。保留虚拟屏、E 与保存 Ledger，不引入 Root、前台输入回退或自动恢复旧工作流。

提示约束：

> 小窗默认只读，接管先撤销 Agent 并排空。所有人工触摸经过 SessionBroker，整段手势结束后才允许交还。双击只改变预览，不能同时点击 App。触摸携带 viewportVersion，放大、切任务和隐藏时取消；输入必须限定虚拟显示和目标 App UID。模拟测试与真实触摸验收分开。

真实拦截记录：新增拥塞取消测试第一次失败。底层 DOWN 阻塞时本地队列满而取消，但恢复后缓冲 MOVE 仍被连续消费；原实现把协程取消当作自动清空队列。逐包派发前增加 ensureActive，保留 NonCancellable 的 CANCEL 清理，防止取消后重放。测试保留原失败条件作为回归。

审查还检查：返回控制权前等待清理；CANCEL 可清理原会话但不能把旧手势转到新预览；UID 定向方法缺失就停止；同一显示不复用到默认屏；标记双击为 UI 操作而不派发 App 双击。具体版本和本地结果见 [本地检查](../evaluation/LOCAL_CHECKS.md)。真实 WindowManager、触摸注入、IME 和屏幕焦点仍未测试。

## 第四轮：Android 层本地集成测试

用户在确认上一轮只跑了 core 逻辑后要求继续。本轮补 Robolectric 的窗口/事件与适配器契约测试，设备继续跳过，沿用 JDK 17 和编译 SDK 35。

约束：运行生产 View 和输入适配器，不复制一套手势算法作为“验证”；窗口、系统输入接收端和无法模拟的 displayId 元数据分别标明。通过稳定 View ID 查控件，模拟事件、控制时钟和配置/权限变化；输出合成画面供布局检查，不能作为真机截图。

实际问题与处理：

- 本地构建停在读取生成目录中的重复、dataless class 文件。通过线程/文件状态定位；使用 Gradle clean 清理生成产物后重建，源码未删除。
- 新增 View ID 时被 show(id) 的参数遮蔽，编译失败；改成 this.id 明确指定 View 属性。
- 适配器在两种 SDK 的测试中都读到 displayId=0；核对 Robolectric 实现后确认默认 Shadow 不实现这个元数据。新增显式元数据 Shadow 与注入接收记录器，保留“只证明参数与反射契约”的边界，没有把它记为生产代码故障。

新增 19 项窗口/事件测试与 8 项适配器契约测试通过。Native Graphics 的合成小窗/放大图已查看，检查按钮、布局和黑边；完整测试/构建结果见 [本地报告](../evaluation/LOCAL_CHECKS.md)。设备输入、焦点、IME、声音与真实账号操作仍未测试。

## 第五轮：小窗文字输入桥

给 Coding Agent 的约束：保持虚拟屏 IME 隐藏；用户明确接管后才能选字段；只做一次 ACTION_SET_TEXT，不做回车、保存或发送。使用现有 Broker 仲裁，草稿绑定 E 与预览版本，切屏/隐藏/交还撤销；本轮继续跳过真机。

审查重点：默认预览仍非焦点；只有显式编辑窗口临时请求本地键盘；指定显示最上层窗口与原节点身份/原值必须匹配；密码字段不枚举；晚到读取不能重开编辑器；重复确认不二次提交；编辑内容不进日志或模型请求。

拦下并修正的初版问题：SET_TEXT 后读回等待可被协程取消，可能提前释放人工输入名额。改为已提交动作的结算使用 NonCancellable，并增加“取消调用方仍持有名额直到结算”的 Android 适配器回归。初版通用错误文案还写成“未写回”；审查指出回执异常无法证明没有副作用，改成“无法确认写回结果”，草稿仍只消费一次。

窗口测试曾在关闭编辑器后立即注入点击得到 0 次转发。原因是关闭提示触发预览重新布局，旧映射按设计失效；测试先完成真实 View 的布局遍历，再发新点击。保留布局变化取消旧输入的约束。中文/多行/清空、多字段选择、原值/节点/布局变化、过期和 UNKNOWN 不重发都有独立检查。

合成文字编辑器渲染图已经查看，字段和确认/取消按钮可见。全部最终计数与构建证据见 [本地报告](../evaluation/LOCAL_CHECKS.md)；真实拼音候选、键盘遮挡/恢复焦点、目标 App 的保存效果仍待设备验证。交还只撤销旧观察并允许新动作，不自动恢复旧任务。

## 第六轮：交还后保留修改并继续

用户要求交还后重新观察并继续，不能覆盖人工修改，继续跳过真机。给 Coding Agent 的约束：保留原授权、计划、预算、已读邮件和游标；先取消并等待旧执行器，再开放 HUMAN；新 E 下先只读观察，禁止旧节点、旧预填 Intent 和旧 Save 票据。

审查发现三个会破坏这个约束的细节：

- 仅重跑旧工作流会再次 ACTION_INSERT/填写。改成检查点与恢复分支，标题/备注经核对和新确认后直接保存当前表单，不再填字段；修订持久化用于后续去重。
- 首次保存前若用户删除来源标记，PREPARED 仍允许创建。增加 HUMAN_HELD，落盘前停在 DRAINING；普通重跑只查询，不能因为没搜到而重新创建。
- 仅检查“两个时间字符串都在页面上”可能误认开始/结束互换。恢复增加接管前页面比较与开始/结束字段角色核对，并把同样规则用于重开证明；编辑页和已保存详情均有回归。

额外检查：重复接管保留第一份人工操作前快照，不把未知改动重新当作基线；确认后页面改变拒绝保存；拒绝确认或 Save 未知时保留现场，不导航到下一事项；旧确认卡、旧执行结果和旧票据均不能影响新 E。本地确认卡使用当前内容，模板中的标题/备注没有用原值替换。

真实构建问题：同步目录中的重复生成 XML 导致 Gradle 哈希读取阻塞。线程与打开文件定位后，终止本次构建、使用工程 clean 重建，源码未删除。Android 测试编译还拦下了不适用的 RuntimeEnvironment 泛型调用，按实际签名修正。测试和能力边界见 [本地报告](../evaluation/LOCAL_CHECKS.md) 与 [恢复规则](RESUME.md)。

## 第七轮：日期时间修改与冲突复查

用户要求保留人工修改的新日期/时间，重查冲突再继续，真机继续跳过。给 Coding Agent 的约束：按明确字段角色解析完整日期和时间，IANA 时区与夏令时校验；不重填表单；事件保留相对提醒、任务保持原截止。旧冲突选择失效，Save 仍用新 E 和一次性页面票据，保存后按新时间重开核实。

关键取舍：原 GUI 冲突检查会导航到日历当天，可能离开人工未保存的表单。恢复新增 CalendarContract 只读查询，以主动 READ_CALENDAR 授权为前提，不增加写权限；读取配置账号的可见日历实例，仅本地展示。缺权限/未同步/目标不唯一明确标为范围不完整，交给用户选择继续或保留页面。确认后再查，区间或覆盖状态变了即停住；当前表单要转提醒或标改约，由用户先接管修改。

审查修正：

- 日期/时间文本允许变化，但保留对应节点身份、布局和其他字段的封印；仅“旧字符串仍在页面”不能复用旧草稿。无年份、重复角色、互相矛盾的文本/描述和夏令时歧义均不接纳。
- 读日历要排除自己的精确来源标记，同时对重复标记降为未知；全天事件按 UTC 编码日期转换为本地整天，重复事件读取实际 Instances，取消和空闲事件不阻塞。
- 确认后的冲突复查发生在恢复保存资格之前；拒绝或变化仍保持 HUMAN_HELD，不推进下一事项。保存后的时间修订用于后续去重，清除旧 choice/choiceDigest。
- Android 测试首次编译发现当前 SDK 不包含 android.test.mock.MockContentResolver，改用已有 Robolectric ContentResolver 与合成 ContentProvider；同时修正 Kotlin 数组追加和跨模块 nullable 属性断言。没有为测试添加生产依赖。

测试使用生产解析器、工作流、GUI 端口与只读查询器；界面树、shell、模型回执及 Provider 游标为合成。测试数、构建和签名见 [本地报告](../evaluation/LOCAL_CHECKS.md)；真实系统 CalendarProvider/权限页面、Google Calendar 字段与云同步边界待真机验证。
