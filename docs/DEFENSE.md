# 30 分钟技术答辩提纲

以下是讲解顺序，待验证能力不使用完成语气。

| 时长 | 主题 | 展示材料 |
| --- | --- | --- |
| 3 分钟 | 用户继续使用主屏，招聘邮件落成真实日程 | 场景、演示、完成边界 |
| 8 分钟 | 为什么采用同机虚拟屏 + shell，为什么默认单 Agent | 架构图、路线表、有效 flags、普通用户 Shizuku 启动步骤 |
| 5 分钟 | 实时观察、单步动作、隐私与时区 | UiElement / Action、隐私出站门、夏冬时和歧义测试 |
| 5 分钟 | 接管和保存：最难的竞态 | E 代次、在途输入排空、WRITE_PENDING / UNKNOWN、重开核实 |
| 5 分钟 | 如何证明不打扰且确实完成 | AC01–AC12；三组对照；录像与日志；失败和未测项 |
| 4 分钟 | 如何指导和审查 AI 代码 | AIDL/CI 修复、原文时间误核实、接管恢复与角色证明审查、125 项行为测试、未解决问题 |

建议能直接回答：

- 两块屏不意味着推理并发。默认单 Agent 减少编排成本，双 Agent 的收益要扣掉 token、CPU 与帧采集代价。
- shell UID 有权限创建显示，不自然保证每个 App 的焦点、输入法、声音都隔离；必须有行为证据。
- 当前暂停可以拒绝新指令，不能撤回系统已经接受的调用，人工授权需等到排空。
- SET_TEXT 与提交搜索分开；日期选择器优先用 Intent 预填并在 GUI 核对；Tasks 单独实现。
- 模型说 Finish 只产生停止边界，持久化验证器决定哪些事项可以报告完成。
- 胶囊点击打开默认只读小窗；明确接管后可单指操作，双击预留给放大，窗口与虚拟屏生命周期分离。代码已接入，设备效果待验证。电脑只是观察者，断开不应改变手机任务控制权。
- 125 项 core 与 121 项 Android 层测试检查编排、事件、窗口、文字与恢复。恢复使用新观察/确认/票据，人工修订持久化，未知保存只查。系统服务、GUI/shell/模型与回执由测试模拟，真实 App、在线模型、焦点与中文键盘仍未验证。
- HarmonyOS 的版本名不能代替 Android API、shell 或原生 APK 能力检测。Mate 60 Pro 目前只记录为待验证候选。
