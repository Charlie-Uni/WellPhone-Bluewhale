每轮保存：commit、手机型号/系统 build、App 版本、模型/参数、屏幕刷新率、网络、镜像开启状态、试验组、输入路径、逐步日志、录像与逐项核实结果。运行产物放 runs/（默认不进 Git，人工脱敏后再提交摘要）。

接管分开记录“请求→本地撤销 E”和“请求→所有输入结算完毕”。撤销 p95≤500ms 是待验证目标，至少 30 次请求，不能声称等于全部系统效果消失。镜像帧延迟不用于精密测量。

性能报告保留每轮数据、失败和观察开销；三次运行适合初步比较，不声称统计显著。SurfaceView 场景说明 gfxinfo/FrameTimeline 覆盖限制。无可信负载数据时只报告固定保守模式。

## 90–120 秒目标演示（未录制）

以下是设备验证后的目标脚本。原地触摸和悬浮放大代码已接入，真实设备效果未验证，双执行 Agent 未实现；不能按这份脚本声称已经完成演示。执行速度尚无实测，若超过时长应缩小展示任务，附完整未加速录像。

使用 [fixtures/mail-scenarios.json](fixtures/mail-scenarios.json)，将三封纯文本邮件发到真实测试标签，预置一个冲突日程。样本域名均为保留测试域名，录制时换成自己控制的会议测试链接，不触发邀请。

| 时间预算 | 画面与行为 |
| --- | --- |
| 0–10 秒 | 主屏给出自然语言目标，小胶囊显示短计划；用户进入微信开始输入 |
| 10–35 秒 | 主屏持续输入，电脑同时镜像真实 A/B 画面，三路叠加同一录制时钟 |
| 35–55 秒 | 甲出现冲突，用户选择“待改约”；Agent 继续乙与丙 |
| 55–75 秒 | 用户原地接管后台窗口，修改当前事项标题后交还；新观察核对、本地确认保存，继续剩余事项；保留原显示 ID |
| 75–90 秒 | 汇总分别说明已核实、人工修改后待检查的边界；停止并排空后用户自愿打开主屏日历核对两事件/一任务 |

本轮任务接管后保留检查点；全部相关会话交还后新观察再继续，未完成编辑先核对，不重新创建表单。另一会话保留独立控制权，单执行器暂停期间不承诺继续执行。

字段写回 VERIFIED 与日历持久化核实分别记录。演示保留来源标记，改受支持的标题/备注/日期/时间；提前主动授权 READ_CALENDAR，新确认展示新时间与复查结果，再查未变后保存并离开重开核实，修订持久化用于去重。另测夏令时歧义/标记删除被阻止、只读权限失败明确范围未知、冲突变化拒绝 Save、Save 未知仅查询。记录指定 App 真实字段与系统 CalendarProvider 数据的兼容和同步边界。显式本地文字编辑临时使用键盘；AC08 的后台不抢焦点测试在未打开编辑器时进行，另测关闭后的恢复。

按真实速度调整到 120 秒；不加速、不拼接不同轮、不提前写好结果，附完整原始录屏。尚未实现的 UI 不进入成功演示。
